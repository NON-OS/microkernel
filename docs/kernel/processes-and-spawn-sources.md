# Processes and capsule spawn: processes and where capsules come from

Part of [Processes and capsule spawn](processes-and-spawn.md).

## Processes and address spaces

Every ring 3 program is a process with its own address space. `create_address_space` gives each one a fresh top level page table and copies the kernel half into it (`src/memory/paging/manager/address_space/create.rs`, `fn create_address_space`), and `allocate` records that table for the process (`src/process/address_space/lifecycle/setup.rs`, `fn allocate`). A thread shares its process's tables through `inherit` (`src/process/address_space/lifecycle/setup.rs`, `fn inherit`) and is held to its process's name and limits when it sends IPC, through `caller_group` (`src/services/registry/peers_check.rs`, `fn caller_group`).

A process moves through the states of `ProcessState`: `New`, `Ready`, `Running`, `Sleeping`, `Stopped`, then `Zombie` and `Terminated` with an exit code (`src/process/core/types.rs`, `enum ProcessState`). [Memory and paging](memory-and-paging.md) and [Scheduler and SMP](scheduler-and-smp.md) cover the tables and the run queues.

## Where capsules come from

- Built into the image. The kernel embeds a capsule's ELF, [identity certificate](../overview/glossary-linux-personality.md#nonos-id-certificate), [manifest](../overview/glossary-linux-personality.md#manifest) and [attestation trailer](../overview/glossary-amnesic-boot.md#attestation-trailer) with `include_bytes!`, as `HELLO_ELF` and its neighbours do (`src/userspace/capsule_hello/embed.rs`, `const HELLO_ELF`). A spawn site gives the name, the service and reply ports and the [capabilities](../overview/glossary-boot-root-record.md#capability) it is willing to grant, as `spawn_hello_capsule` does for `app.hello` on port 4810 with reply port 4811 (`src/userspace/capsule_hello/spawn.rs`, `fn spawn_hello_capsule`). Its `HELLO_ELF` is embedded only in a kernel built with the `nonos-capsule-hello` feature (`src/userspace/capsule_hello/embed.rs`, `const HELLO_ELF`).
- Installed later. The installer reads the same four artifacts from the store and passes them to `MkCapsuleLoad` by pointer; `load_capsule_from_vfs` takes the service name and both [endpoints](../overview/glossary-dma-pool.md#endpoint) from the signed manifest and refuses a request for any bit the manifest does not declare, with a `[CAP-DENY] load: … asked beyond its manifest` line (`src/kernel_core/process_spawn/capsule_spawn/from_vfs/load/asked.rs`, `fn within_manifest`). The installer asks for the manifest's own set when its sender names none, as the shell and the Terminal do (`userland/capsule_installer/src/server/handlers/load_by_name/own_caps.rs`). What the capsule would install must lie within the capabilities of the process it is loaded for, the ambient set counted as held, unless that process is a launcher: it holds `SpawnWindow`, or `Admin` in its place. A load outside is refused, never narrowed, with a `[CAP-DENY] load: … missing caps` line (`from_vfs/load/bound.rs`, `fn check`). The call needs `CoreExec`, `IPC` and `Memory` (`src/syscall/contract/cap_table/mk_proc.rs`, `fn check`).
- Run as a tool. `MkToolRun` starts a baked tool, or the Linux personality as `tool.linux` or `tool.qwen`, as the caller's child, under the same bound: the tool's installed set within the caller's unless the caller is a launcher, else EPERM and a `[CAP-DENY] tool:` line (`src/userspace/tool_capsules/bound.rs`, `fn check`). No name is exempt (`EXEMPT` is empty): `tool.model-fetch` is bounded too, and the Linux personality's install role, which runs it for `linux install`, asks for `StreamImport` itself, the one role that does.
- On behalf of another process. A caller holding `SpawnBroker` may name a live pid as the new capsule's parent; `attest` is the only way to build that attribution (`src/kernel_core/process_spawn/capsule_spawn/attested_parent.rs`, `fn attest`).
- Linux guests. `MkForeignSpawn` creates a process for the [Linux personality](../overview/glossary-linux-personality.md#linux-personality) that holds no capabilities at all: `install_spawn` gives it an empty word (`src/process/foreign/spawn.rs`, `fn sys_foreign_spawn`); its Linux system calls go to the supervising capsule. [Linux personality](../userland/linux-personality.md) covers it.
