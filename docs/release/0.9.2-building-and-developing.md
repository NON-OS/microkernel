# NONOS 0.9.2 release notes: Building and developing

Part of [NONOS 0.9.2 release notes](0.9.2.md).

### Building and developing

- In the run recorded for this commit, 9 of the 143 flake checks failed and 1
  did not evaluate. `proofs-rtl8169_proofs` passed its tests and then failed on
  a clippy lint in `userland/capsule_driver_rtl8169/src/log/line.rs`;
  `proofs-usb_msc_proofs` and `proofs-xhci_proofs` failed on clippy too;
  `static-hygiene`, `static-abi`, `static-tree`, `inputs`, `nonos-verify` and
  `busybox-source` failed; `proofs-model_fetch_proofs` did not evaluate. The
  `inputs` result and the one that did not evaluate may come from a tree without
  the market operator's public key. A check that does not evaluate stops `make
  check` as a whole, so run the check you need by name. See [State of the
  checks](../build/ci.md#state-of-the-checks-at-this-commit) and [The Nix
  flake](../build/nix-flake.md).
- Every one of the latest 300 commits carries `[skip ci]`, so no push workflow
  ran on them, and `cut-release` passes a commit with no check runs. See
  [CI](../build/ci.md#skip-ci).
- `python3 tools/nix/inputs.py` rewrites `tools/nix/inputs.json` whatever
  argument it is given; only `--check` is read-only. See [The Nix
  flake](../build/nix-flake.md).
- The published `abi/` files disagree with the kernel in places: the argument
  lists of `MICL`, `MPGT`, `MIRA`, `MIRP` and `GDIM`, the width of the `MPCW`
  value, the 256 MiB `max_mmap_bytes` against the kernel's 1 GiB, and the token
  layout in `abi/caps.toml`. The code decides. See [Stability in
  0.9.2](../abi/abi-stability-in-092.md#stability-in-092).
- In a capsule built on Rust `std`, `TcpStream` opens a plain socket and does
  not follow the default network. See [Rust std for
  capsules](../userland/libc.md#rust-std-for-capsules).
- The five USB network capsules ask for the mask 0x200018, which grants
  InputSource and no Debug, though the comment in their `Capsule.mk` reads it as
  Debug. They are in no image. See [USB
  networking](../drivers/ethernet/usb-net.md).
- The structured log macros, `log_info!`, `warn!` and the rest, write nothing:
  no code initialises the log manager. Only lines written straight to the
  console reach it. See [The structured
  log](../kernel/logging.md#the-structured-log-and-the-debug-ring).
- aarch64 builds only with `nonos-arch-preview`, with no loader and no release
  image; riscv64 does not build into a kernel. See
  [Architectures](../architectures/README.md).
