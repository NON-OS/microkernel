# NONOS 0.9.3 release notes: Upgrade notes

Part of [NONOS 0.9.3 release notes](0.9.3.md).

## Upgrade notes

How an installed system moves to a newer release depends on the release that
made its disk.

### From 0.9.2 or earlier: install over it

A disk made before 0.9.3 keys its data volume to its own kernel, so no newer
release opens it, and the installer offers only the install. The Confirm
screen says `NØNOS keyed to its own kernel: its data cannot be kept`
(`MadeBefore` in `userland/nonos_disk/src/keep/why.rs`).

1. Get the image and write it to a stick ([Get an
   image](../install/get-an-image.md), [Write a USB
   stick](../install/usb-stick.md)).
2. Boot the stick, choose `Install NØNOS` in the boot menu and answer setup.
3. On the Disks screen choose the disk whose row says `NONOS installed`. The
   Confirm screen warns `holds NØNOS; its store and data volume are lost`.
4. Type the disk's word, let the installer write and read back, remove the
   stick and restart.

Nothing carries over from the old disk. The old store, the programs installed
there, anything kept there and the old data volume are erased. The new disk
gets setup's answers, the wallpapers they keep and the signed programs the
stick carries. Answers an earlier release kept on the stick keep everything but
the wallpaper, which reads as `Canyon neon` ([Update](../install/update.md)).

### From a disk made by 0.9.3: update and keep the data

A data volume that 0.9.3 formats on a boot the release approved has a random
key, wrapped under a key the TPM gives only a kernel the release approved. A
signed update keeps it ([Update](../install/update.md#two-ways-to-update)):

1. Start the installed system, open the Install tile on the dock, and press P
   beside `Prepare this computer for an update`. Go on when it says `Ready.
   Restart from the new NØNOS stick and choose Update NØNOS (keep my data).
   Until you do, your data volume opens without the bootloader check for one
   start.` A volume kept by a passphrase needs no prepare.
2. Write the newer image to a stick, boot it, choose `Install NØNOS` and
   answer setup.
3. On the Disks screen choose the disk that holds the old system.
4. On the Confirm screen, titled `Your data volume will be kept`, leave
   `Update NØNOS (keep my data)` lit, read its `kept` and `not kept` rows, type
   the disk's word and press Enter. The Done screen says `Updated`.

An update keeps the data volume, its key header, the disk plan and the
partition table. It does not keep store apps, settings changed since setup, the
wallet's vault or saved Wi-Fi networks (`describe_keep` in
`userland/nonos_disk/src/describe/keep_rows.rs`). From the prepare until the
next boot, an approved kernel opens the volume whatever bootloader measured it,
so prepare right before the update ([The
handover](../security/device-secrets-and-keys.md#the-handover)).

### What to know either way

- Write down the wallet's recovery words first. The sealed copy NONOS keeps
  does not open after a kernel or firmware change, and neither way carries
  the wallet's vault ([Wallet](../using/wallet.md)).
- A Linux app's home is gone at power off in any case, so a Monero wallet
  comes back only from its seed ([Monero wallet](../using/monero.md)).
- The key that seals saved Wi-Fi networks is derived under PCRs 0, 4, 7 and 9
  (`BOUND_PCRS` in `src/security/tpm/machine_key/pcrs.rs`), so a new kernel
  gives another key. After a firmware update or a Secure Boot change the
  installed data volume stays closed, whichever way it was keyed. The kernel
  never formats over a volume it cannot open.
- `nonos.toml` keeps `rollback_index` at 1 in this release. On a machine with
  a TPM, a release that raises its index raises the rollback floor the first
  time its stick boots, and an older system on the disk is then refused with
  `This kernel is older than allowed` ([Update](../install/update.md#the-rollback-floor)).
- The kernel keeps the disk the loader was read from, and never another NONOS
  disk in its place ([Update](../install/update.md#what-carries-over)).
- An update from one release to another is not tested in this release. The
  update lane ran on QEMU between two development images of one tree
  ([s1-k1-update](../release-evidence/0.9.3/s1-k1-update/README.md)).

[Update](../install/update.md) has the details and the code behind each step.
