# NONOS 0.9.3 release notes: Upgrade notes

Part of [NONOS 0.9.3 release notes](0.9.3.md).

## Upgrade notes

There is no in-place update in 0.9.3. To move an installed system to 0.9.3,
install it over the old one:

1. Get the image and write it to a stick ([Get an
   image](../install/get-an-image.md), [Write a USB
   stick](../install/usb-stick.md)).
2. Boot the stick, choose `Install NØNOS` in the boot menu and answer setup.
3. On the Disks screen choose the disk whose row says `NONOS installed`. The
   Confirm screen warns `holds NØNOS; its store and data volume are lost`.
4. Type the disk's word, let the installer write and read back, remove the
   stick and restart.

What to know before you start:

- Nothing carries over from the old disk. The old store, the programs
  installed there, anything kept there and the old data volume are erased.
  The new disk gets setup's answers, the wallpapers they keep and the signed
  programs the stick carries. Answers an earlier release kept on the stick
  keep everything but the wallpaper, which reads as `Canyon neon`
  ([Update](../install/update.md)).
- Write down the wallet's recovery words first. The sealed copy NONOS keeps
  does not open after a kernel or firmware change, and the old data volume is
  erased ([Wallet](../using/wallet.md)).
- A Linux app's home is gone at power off in any case, so a Monero wallet
  comes back only from its seed ([Monero wallet](../using/monero.md)).
- The data volume key and the key that seals saved Wi-Fi networks are derived
  under PCRs 0, 4, 7 and 9 (`BOUND_PCRS` in
  `src/security/tpm/machine_key/pcrs.rs`). A new kernel gives another key, so
  0.9.3 opens no data volume an older release made. After a firmware update or
  a Secure Boot change, the installed volume stays closed. The kernel never
  formats over a volume it cannot open.
- `nonos.toml` keeps `rollback_index` at 1 in this release. On a machine with
  a TPM, a release that raises its index raises the rollback floor the first
  time its stick boots, and an older system on the disk is then refused with
  `This kernel is older than allowed` ([Update](../install/update.md#the-rollback-floor)).
- The kernel keeps the disk the loader was read from, and never another NONOS
  disk in its place ([Update](../install/update.md#what-carries-over)).
- An update from one release to another is not tested in this release.

[Update](../install/update.md) has the details and the code behind each step.
