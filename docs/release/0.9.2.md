# NONOS 0.9.2 release notes

What NONOS 0.9.2 adds, the hardware it runs on, what does not work yet, and how to move an installed system to it.

NONOS 0.9.2 runs on every core of an x86_64 processor. The kernel starts every CPU the firmware enables, up to 256, and schedules processes on all of them, in every build profile. See [Scheduler and SMP](../kernel/scheduler-and-smp.md).

To try it, start with [Installing NONOS](../install/README.md). Once it runs, [Using NONOS](../using/README.md) walks through the desktop and its programs.

## What is new

### Install and keep a system

- Install NONOS on an internal disk. Choose `Install NØNOS` in the boot menu, `Install to this computer` in setup, or the Install tile on the dock. The installer shows what this boot proved and offers the NVMe, SATA, Intel eMMC and virtio disks it can write. You confirm with a short word for the disk, the last four characters of its serial when they are printable. It then writes the loader, the kernel, the package store and room for an encrypted data volume, and reads back every sector it wrote. See [Install to disk](../install/install-to-disk.md).
- An installed system keeps setup's answers, the values Settings keeps, saved Wi-Fi networks, the wallet's sealed files, Qwen models on the data volume, NONOS packages installed with `pkg install`, and files you keep from the Terminal with `keep`. Everything but the Qwen models is kept in the package store, which is not encrypted. Saved networks, the wallet's sealed files and the data volume need a TPM. The disk store holds up to 512 entries and 96 MiB of loaded files, the signed programs it already carries included. Files made in Files or Editor are not kept; see [Known issues](#known-issues) and [Files](../using/files.md#what-is-kept-after-power-off).

### Apps and the desktop

- About has a Proofs screen. Its headline says in one line whether this boot is attested and whether its traffic is anonymous, and a part that could not be read shows as unknown, never as a pass. See [About and its Proofs screen](../using/desktop.md#about-and-its-proofs-screen).
- A click on a window raises it and gives it the keyboard in the same press. See [Windows](../using/desktop.md#windows).
- Install a Qwen tier from the Marketplace's `Models` tab, or with `qwen get` in the Terminal. The model files download over the Anyone network, each must match its pinned SHA-256 before the tier counts as installed, and a chat then runs with no network connection. See [Qwen language models](../using/local-ai.md) and [Marketplace](../using/marketplace.md).
- Twelve more Linux programs come in standard images, built from pinned sources: `sqlite3`, `perl`, `tclsh`, `mruby`, `qjs`, `jq`, `gojq`, `rg`, `fd`, `nano`, `make` and `openssl`. Run them from the Terminal with `linux`, beside `sh`, `python3`, `lua`, `zstd` and `john`. See [Linux programs](../using/linux-programs.md).
- The keyring seals and opens the wallet's account key and recovery words for the wallet alone, so no other program can have the keyring open or replace them. A program that holds Crypto can still derive the key behind them itself, as [Security limits](#security-limits) says. See [Wallet](../using/wallet.md) and [Protections and limits](../security/protections-and-limits.md).

### Networking and privacy

- Programs that open their own connections take their route from one rule in `nonos_route_link`. A default network that cannot be read counts as the Nym mixnet, never as Direct. When the chosen network is not running, the connection fails and says so, and nothing falls back to another network. See [Privacy networks](../using/privacy-network.md).
- The browser and the Terminal's `curl`, `git clone` and `git push` follow the default network, and a Browser window can switch its own. The Terminal's `ping`, `nslookup`, `pull` and `push` run only when Direct is the default. See [Which programs follow the choice](../using/privacy-network.md#which-programs-follow-the-choice) and [The Browser](../using/browser.md#which-network-a-page-leaves-through).
- The wallet reads the chain over Nym or Anyone and never directly. Under a Direct default it uses Nym, or Anyone when Nym is not running. See [Wallet](../using/wallet.md).
- Downloads for installs, Qwen models and Linux packages alike, go over the Anyone network whatever the default is. `qwen get --direct` in the Terminal, or `d` in the Marketplace, takes one Qwen download directly. See [Privacy networks](../using/privacy-network.md#which-programs-follow-the-choice).
- One Wi-Fi join engine serves both Wi-Fi drivers. It runs WPA2-Personal and WPA3-Personal (SAE) with CCMP. On a network that offers both, the RTL8821CE driver joins with WPA3 first, and joins again with WPA2 when WPA3 does not finish for any reason but a wrong password. See [Wi-Fi and networking](../using/wifi-and-networking.md#which-networks-can-be-joined).
- The Intel Wi-Fi driver boots firmware, scans and joins WPA2 and WPA3 networks on the SO platforms: AX211, and AX201 modules on those platforms. This path has run only against a modelled device. See [Intel Wi-Fi](../drivers/wifi/iwlwifi.md).
- The network drivers in the image draw a new locally administered station address at each bring-up instead of using the card's factory address. See [Threat model](../overview/threat-model.md).

### Isolation and the kernel

- On Intel VT-d machines the IOMMU confines device DMA. Every image turns translation on at boot and denies a device the boot scan did not find. Each driver capsule gets its own IOMMU domain, so a PCI device it claims behind a unit in service reaches only the buffers granted to it, and a claim that unit cannot confine is refused. See [IOMMU](../kernel/iommu.md).
- Device drivers answer only the services named for them. A wired card's driver takes only `net.core` and `net.l2`, a Wi-Fi card's driver takes `net.core`, Settings and setup, the USB controller takes the USB keyboard and storage drivers, and the keyboard drivers take only the kernel. No other program can put raw frames on the wire or read keystrokes from a driver. See [Who may talk to a driver](../drivers/README.md#who-may-talk-to-a-driver).
- The NVMe, SATA and virtio-blk drivers serve raw sectors only to the kernel's own client and to holders of the StoreWrite capability, and ask the kernel on every request. See [Storage drivers](../drivers/storage/README.md).
- The file store answers only the kernel and holders of the FileSystem capability. See [Design principles](../overview/design-principles.md).
- A send by process id must pass the gate of every endpoint the target serves, as a send by name does. See [IPC](../kernel/ipc.md).
- Releasing a device stops its bus mastering before its DMA buffers are freed, and `MkMunmap` or a fixed `MkMmap` over the broker's device windows is refused. See [The broker ABI](../abi/broker.md) and [Hardware broker](../kernel/hardware-broker.md).
- Inboxes are budgeted in bytes as well as messages: 96 MiB for all inboxes together, 16 MiB for one inbox, and half of that for one sender. One caller holds at most 8 of the 64 replies a service may owe. Each call carries its own correlation token, and a reply reaches only the caller with that token. See [IPC](../kernel/ipc.md).
- Init's watch list names 30 core services, among them the network stack, the file store, the keyring and the display. When one ends, init starts it again, at most 8 times. Drivers, apps, setup, the installer and the Linux personality end on purpose and are not restarted. See [Architecture in one diagram](../overview/architecture.md).
- The kernel clock multiplies in 128 bits, so it does not wrap on a long uptime. See [Timers](../kernel/timers.md).
- The `hardened` and `airgapped` build profiles drop `capsule-serial-debug`, so no capsule there gets the Debug grant that lets it write to the serial console. See [Logging](../kernel/logging.md).
- A driver that starts through the shared bring-up in `nonos_libc` exits at once with status 2 when its device is absent. A device that fails bring-up is tried 7 times, with a pause that starts at 100 ms and doubles up to 3.2 s, and the driver then exits with status 6. The kernel prints an `[EXIT]` line for a driver that ends with a nonzero status, so the console says why even when the driver holds no Debug. See [Drivers](../drivers/README.md) and [Logging](../kernel/logging.md).
- `scripts/cap_audit.py --strict` compares every capsule's capability mask with the calls its code makes, and `scripts/check_mirror_caps.py` holds each kernel spawn file and README to its manifest. At this commit the strict audit reports no failures, with the `attack` and `toolkit` capsules exempt, and the mirror check finds no grant wider than its manifest. See [Design principles](../overview/design-principles.md) and [Checking the security claims yourself](../security/checking-the-claims.md).

### Drivers and the build

- The NVMe driver refuses a doorbell stride that would reach past the registers it mapped, waits as long as the controller's CAP.TO asks, up to 127.5 s, and keeps each command within MDTS. See [NVMe](../drivers/storage/nvme.md).
- The HD Audio driver binds MSI-X, then MSI, then a legacy line when firmware routed one, and otherwise runs polled, so a controller whose firmware left no interrupt line is still driven. See [Audio drivers](../drivers/audio.md).
- The seal's last check rebuilds the kernel and the loader with `nix build` and stops unless they are the bytes it sealed. See [Reproducible builds](../build/reproducible-builds.md).

## Supported hardware

NONOS 0.9.2 runs on x86_64 machines with UEFI firmware. [The hardware support matrix](../hardware/MATRIX.md) lists every chip and id the drivers match, with its state and what that state rests on. By class:

| Class | Works | Partial, refused or not supported |
|---|---|---|
| Processor | x86_64, every core the firmware enables, up to 256; idle performance cores take new work first on Intel hybrid parts | aarch64 is a preview under QEMU; riscv64 does not build into a kernel |
| Platform | UEFI; TPM 2.0 over FIFO or CRB; Intel VT-d DMA remapping | AMD-Vi and interrupt remapping are not built in; Secure Boot needs the NONOS db certificate enrolled; the power button reaches the desktop, which cannot power off |
| Display | the UEFI framebuffer; virtio-gpu | no native GPU driver |
| Storage | NVMe; AHCI SATA, Intel RST in RAID mode; Intel eMMC; USB mass storage on the machine's own ports; virtio-blk | Intel VMD bring-up has not run on hardware; the Intel eMMC host 8086:9d2b is served only beside a SATA controller; no SD card driver |
| USB | xHCI; HID keyboards, mice and tablets on the machine's own ports | devices behind a hub; EHCI, OHCI and UHCI controllers |
| Input | PS/2 keyboard and mouse; I2C-HID touchpads on Intel LPSS or an ACPI-declared controller | I2C-HID touchscreens; a PS/2 touchpad runs as a plain mouse |
| Audio | HD Audio analog outputs: speakers, headphones and line out | HDMI and DisplayPort audio; Intel SST and DSP-only machines; AMD ACP; microphones |
| Wi-Fi | Realtek RTL8821CE | Intel cards on SO platforms, modelled only; the other Intel cards from the 7260 to the AX210 family are refused; every other chip, Intel BE200 and BE201 among them, has no driver |
| Ethernet | virtio-net in a virtual machine | e1000, RTL8139 and the RTL8169 family carry a receive fault; e1000e, igc and USB adapters are in no image |

Real hardware, for Wi-Fi on RTL8821CE (scan, join, DHCP, DNS, browser), the local Qwen model offline, the Linux programs sh, python3, sqlite3 and john, the installer to an internal NVMe disk and booting from it, the I2C-HID touchpad on Intel LPSS, the PS/2 keyboard with layouts, Intel HD Audio, the power button and the volume keys: Works on an x86_64 laptop (Intel Gemini Lake, 8 GB), maintainer hardware report, 6 October 2026; the image commit was not recorded.

Nothing else has been run on real hardware for this release. [Reporting a machine](../hardware/report.md) says how to add a report for yours.

## Known issues

### Using NONOS

- The desktop cannot shut down or restart the machine. The Power key, from the keyboard or the ACPI power button, shows `Power off is not available from the desktop`; the power service is built but not started. To turn the machine off, hold the power button for four seconds. That forced power-off skips the memory wipe an orderly shutdown runs. When the kernel cannot read the power button itself, its log line points to a Shut Down menu that does not exist. See [Keys the desktop answers](../using/desktop.md#keys-the-desktop-answers), [Platform devices](../drivers/platform.md) and [Device secrets and keys](../security/device-secrets-and-keys.md).
- Files and Editor never ask for a file to be kept, so what you make there is gone at power off, even on an installed system. To keep a file, make it in the Terminal and run `keep` on it. See [Files](../using/files.md#what-is-kept-after-power-off).
- Without a TPM, an installed system keeps its data volume closed. See [After the install](../install/install-to-disk.md#after-the-install).
- Settings has no keyboard layout row, no switch to turn back on an app turned off at setup, and no shutdown. See [Settings](../using/settings.md#what-settings-does-not-have).
- The Wi-Fi notes in Settings and setup are older than the code: they say WPA3 cannot be joined and open networks can. WPA3-Personal joins; open, TKIP, Enterprise and hidden networks do not. There is no IPv6 and no Wi-Fi in the `qemu` image. See [Limits in this release](../using/wifi-and-networking.md#limits-in-this-release).
- The Settings note under `Default network` says Qwen downloads take that network, and setup's Network route step describes model downloads under each choice as if they did. They go over Anyone whatever the default. See [Privacy networks](../using/privacy-network.md#which-programs-follow-the-choice).
- `net.nym` and `net.anon` start on every boot that starts the network, whatever the default. `net.nym` reaches for a gateway and `net.anon` builds a circuit even when nothing uses them. Your local network can see that this machine runs Nym and Anyone, under Direct too. See [Threat model](../overview/threat-model.md).
- A booted image carrying traffic through a live Nym gateway or a live Anyone circuit is not tested in this release; the route code passes its host tests. See [What is tested](../using/privacy-network.md#what-is-tested).
- For an Intel card it cannot start, the Settings panel suggests `USB Wi-Fi`. NONOS has no USB Wi-Fi driver. See [Intel Wi-Fi](../drivers/wifi/iwlwifi.md).
- Programs started with `linux` have no network, are told the machine has one CPU though the kernel runs their threads on any core, and keep nothing they write except through a `>` redirect. See [What does not work](../using/linux-programs.md#what-does-not-work).
- The Marketplace lists only the Qwen tiers: no Linux packages and no NONOS apps. It reads a signed catalogue built into the image, and `qwen get` reads another. In an image built without them every Marketplace tab is empty and `qwen get` exits with status 3. See [Marketplace](../using/marketplace.md) and [Qwen language models](../using/local-ai.md).
- The volume starts at full on every boot and is not kept. See [Sound and media](../using/audio.md).
- There is no login and no password. `Lock the screen` in the wallet hides balances and actions, and `Open the wallet` brings them back without a passphrase. See [First boot](../install/first-boot.md) and [Wallet](../using/wallet.md#what-the-wallet-does-not-do).
- The Terminal's `log` reads a copy of the console that only images built with `capsule-serial-debug` keep; `hardened` and `airgapped` images keep none. Most drivers hold no Debug, so their own lines never print: read the kernel's `[DRIVER-...]` and `[EXIT]` lines instead. Kernel lines written through the structured log never print anywhere, among them the `[CAP-DENY]` capability refusals and the `[DATA]` line that says a data volume stays closed for want of a machine key. See [Logging](../kernel/logging.md) and [Reporting a machine](../hardware/report.md).

### Hardware

- Wired Ethernet through the e1000, RTL8139 and RTL8169 drivers receives no frames. `net.core` takes their answer to its first receive-batch probe as a yes, then drops every register snapshot they send back as an unreadable batch, so DHCP gets no lease through them. This is read from the code; no run on this commit shows it either way. Transmit and virtio-net are not affected. See [The receive fault](../drivers/ethernet/README.md#the-receive-fault).
- Devices plugged into a USB hub do not work. Plug keyboards, mice and USB sticks straight into a port of the machine. See [USB hubs](../drivers/usb/hubs.md).
- No 0.9.2 image carries the e1000e, igc or USB network drivers, so no Intel I217, I218, I219, I225 or I226 port, USB Ethernet adapter or USB tethering works. See [Intel Ethernet](../drivers/ethernet/intel.md) and [USB networking](../drivers/ethernet/usb-net.md).
- Intel Wi-Fi joins only on SO platforms, and only against a modelled device so far. It has no interrupt-driven operation, no firmware restart and no power save. See [Intel Wi-Fi](../drivers/wifi/iwlwifi.md#not-supported).
- The kernel brings up an Intel VMD's private PCI domain itself, but that has not run on a machine with a VMD. If the drive behind it does not show, set the firmware's storage mode to AHCI or turn VMD off. See [Intel VMD](../drivers/storage/vmd.md).
- The seal signs the loader for Secure Boot only with the NONOS db key. Unless that certificate is enrolled in your firmware, turn Secure Boot off and boot Standard; booting with Secure Boot on is not tested in this release. Hardened and Air-Gapped boots need a TPM, and the menu does not list the TPM under Air-Gapped. See [Requirements](../install/requirements.md) and [Boot modes](../install/boot-modes.md).
- The installer refuses a disk under 2177 MiB or with 4096-byte logical blocks, and never offers a USB disk. See [Install to disk](../install/install-to-disk.md).
- Physical memory above 64 GiB is not used. See [Frame allocator](../kernel/frame-allocator.md).

### Security limits

[Protections and limits](../security/protections-and-limits.md#what-nonos-does-not-address) states each of these with the code behind it.

- On a machine with no remapping unit in service, or with AMD-Vi only, a driver's claim goes ahead unconfined and the boot log says so. A device no driver has claimed stays identity-mapped, and a controller found through ACPI, or a device behind a remapping unit outside PCI segment 0, is never confined. See [IOMMU](../kernel/iommu.md#when-remapping-is-not-in-service).
- Without a TPM, every boot entry but Hardened and Air-Gapped boots with rollback protection off, so an older signed kernel boots. Without a TPM, or when the loader hands over no TCG log, the kernel's check of the loader rests on the loader's own word. Clearing the TPM starts the rollback floor again at 0. With Secure Boot off, an image sealed whole with other keys passes the loader's and the kernel's checks, though the TPM gives it another machine key. See [Boot chain and signatures](../security/boot-chain-and-signatures.md#secure-boot) and [Rollback protection](../security/rollback-protection.md).
- The package store is written to the disk unencrypted. Only the data volume, and records a program seals itself, are protected there.
- The shutdown wipe misses kernel statics, among them the data volume key, and a live stick's in-memory volume. A panic, a forced power-off or a power cut skips the wipe, and in this release only the installer's restart runs it.
- The TPM exchange that derives machine keys is unbound and unsalted, so a key crosses a discrete TPM's bus in the clear. Any program holding Crypto can derive any machine key label except the kernel's own, the wallet's vault root and the saved Wi-Fi key among them. See [Device secrets and keys](../security/device-secrets-and-keys.md).
- On x86_64 each system call fills the return stack buffer and sets IBRS where the CPU has it. STIBP and SSBD are set at boot on the boot CPU only. VERW on exit, IBPB on context switch, the L1D flush and KPTI are not in effect.
- The image-wide capability ceiling is computed and logged, not enforced: a capsule that asks for more prints `[CEILING] not enforced, would refuse` and still starts. See [Build profiles](../build/profiles.md).
- The kernel image sits at a fixed address; there is no kernel address randomisation. The kernel has no stack canaries, and the kernel stack each process makes its system calls on has no guard page. See [KASLR](../kernel/memory-and-paging.md#kaslr) and [Stack guards](../kernel/memory-and-paging.md#stack-guards).

### Building and developing

- In the run recorded for this commit, 9 of the 143 flake checks failed and 1 did not evaluate. `proofs-rtl8169_proofs` passed its tests and then failed on a clippy lint in `userland/capsule_driver_rtl8169/src/log/line.rs`; `proofs-usb_msc_proofs` and `proofs-xhci_proofs` failed on clippy too; `static-hygiene`, `static-abi`, `static-tree`, `inputs`, `nonos-verify` and `busybox-source` failed; `proofs-model_fetch_proofs` did not evaluate. The `inputs` result and the one that did not evaluate may come from a tree without the market operator's public key. A check that does not evaluate stops `make check` as a whole, so run the check you need by name. See [State of the checks](../build/ci.md#state-of-the-checks-at-this-commit) and [The Nix flake](../build/nix-flake.md).
- Every one of the latest 300 commits carries `[skip ci]`, so no push workflow ran on them, and `cut-release` passes a commit with no check runs. See [CI](../build/ci.md#skip-ci).
- `python3 tools/nix/inputs.py` rewrites `tools/nix/inputs.json` whatever argument it is given; only `--check` is read-only. See [The Nix flake](../build/nix-flake.md).
- The published `abi/` files disagree with the kernel in places: the argument lists of `MICL`, `MPGT`, `MIRA`, `MIRP` and `GDIM`, the width of the `MPCW` value, the 256 MiB `max_mmap_bytes` against the kernel's 1 GiB, and the token layout in `abi/caps.toml`. The code decides. See [Stability in 0.9.2](../abi/README.md#stability-in-092).
- In a capsule built on Rust `std`, `TcpStream` opens a plain socket and does not follow the default network. See [Rust std for capsules](../userland/libc.md#rust-std-for-capsules).
- The five USB network capsules ask for the mask 0x200018, which grants InputSource and no Debug, though the comment in their `Capsule.mk` reads it as Debug. They are in no image. See [USB networking](../drivers/ethernet/usb-net.md).
- The structured log macros, `log_info!`, `warn!` and the rest, write nothing: no code initialises the log manager. Only lines written straight to the console reach it. See [The structured log](../kernel/logging.md#the-structured-log-and-the-debug-ring).
- aarch64 builds only with `nonos-arch-preview`, with no loader and no release image; riscv64 does not build into a kernel. See [Architectures](../architectures/README.md).

## Upgrade notes

There is no in-place update in 0.9.2. To move an installed system to a newer release, install the new release over the old one:

1. Get the image and write it to a stick ([Get an image](../install/get-an-image.md), [Write a USB stick](../install/usb-stick.md)).
2. Boot the stick, choose `Install NØNOS` in the boot menu and answer setup.
3. On the Disks screen choose the disk whose row says `NONOS installed`. The Confirm screen warns that its store and data volume are lost.
4. Type the disk's word, let the installer write and read back, remove the stick and restart.

What to know before you start:

- Nothing carries over from the old disk. The old store, the programs installed there, anything kept there and the old data volume are erased. The new disk gets setup's answers, the wallpapers they keep and the signed programs the stick carries. NONOS has no way to copy files off the old disk first.
- Write down the wallet's recovery words before you update. The sealed copy NONOS keeps does not open after a kernel or firmware change, and the old data volume is erased.
- On a machine with a TPM, booting a newer release's stick once raises the TPM rollback floor when that release raised its rollback index. The older system on the disk is then refused with `This kernel is older than allowed`, and there is no way back to it on that machine short of clearing the TPM, which loses every key the TPM derives. Without a TPM the loader keeps no floor, and Hardened and Air-Gapped refuse to boot.
- The data volume key and the key that seals saved Wi-Fi networks are derived under PCRs 0, 4, 7 and 9. After a firmware update or a Secure Boot change, the installed volume stays closed and saved networks read `Sealed under a different boot state`. The kernel never formats over a volume it cannot open, and putting the firmware and the Secure Boot setting back gives the old key back. Clearing the TPM loses these keys for good.
- Remove the stick after installing. While a stick that carries NONOS is plugged in, the kernel keeps the boot's state on it before any internal disk.
- An update from one release to another is not tested in this release.

[Update](../install/update.md) has the details and the code behind each step.
