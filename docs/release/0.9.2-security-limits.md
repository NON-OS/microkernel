# NONOS 0.9.2 release notes: Security limits

Part of [NONOS 0.9.2 release notes](0.9.2.md).

### Security limits

[Protections and
limits](../security/protections-and-limits-what-nonos-does.md#what-nonos-does-not-address)
states each of these with the code behind it.

- On a machine with no remapping unit in service, or one that does not remap
  interrupts, a driver's claim is refused and the boot log says so. A device no
  driver has claimed is blocked but for the memory firmware reserved for it, and
  a controller found through ACPI, or a device behind a remapping unit outside
  PCI segment 0, is never confined.
  See
  [IOMMU](../kernel/iommu-per-capsule-domains.md#when-remapping-is-not-in-service).
- Without a TPM, every boot entry but Hardened and Air-Gapped boots with
  rollback protection off, so an older signed kernel boots. Without a TPM, or
  when the loader hands over no TCG log, the kernel's check of the loader rests
  on the loader's own word. Clearing the TPM starts the rollback floor again at
  0. With Secure Boot off, an image sealed whole with other keys passes the
  loader's and the kernel's checks, though the TPM gives it another machine key.
  See [Boot chain and
  signatures](../security/boot-chain-and-signatures.md#secure-boot) and
  [Rollback protection](../security/rollback-protection.md).
- The package store is written to the disk unencrypted. Only the data volume,
  and records a program seals itself, are protected there.
- The shutdown wipe misses kernel statics, among them the data volume key, and a
  live stick's in-memory volume. A panic, a forced power-off or a power cut
  skips the wipe, and in this release only the installer's restart runs it.
- The TPM exchange that derives machine keys is unbound and unsalted, so a key
  crosses a discrete TPM's bus in the clear. Any program holding Crypto can
  derive any machine key label except the kernel's own, the wallet's vault root
  and the saved Wi-Fi key among them. See [Device secrets and
  keys](../security/device-secrets-and-keys.md).
- On x86_64 each system call fills the return stack buffer and sets IBRS where
  the CPU has it. STIBP and SSBD are set at boot on the boot CPU only. VERW on
  exit, IBPB on context switch, the L1D flush and KPTI are not in effect.
- The kernel image sits at a fixed address; there is no kernel address
  randomisation. The kernel has no stack canaries, and the kernel stack each
  process makes its system calls on has no guard page. See
  [KASLR](../kernel/memory-and-paging.md#kaslr) and [Stack
  guards](../kernel/memory-and-paging.md#stack-guards).
