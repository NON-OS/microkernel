# NONOS 0.9.3 release notes: Supported hardware

Part of [NONOS 0.9.3 release notes](0.9.3.md).

## Supported hardware

NONOS 0.9.3 runs on x86_64 machines with UEFI firmware. [The hardware support
matrix](../hardware/MATRIX.md) lists every chip and id the drivers match, with
its state and what that state rests on. This page gives what changed for 0.9.3.

### Wi-Fi

Every Wi-Fi driver below is in the standard image, and the kernel starts one
only when the boot scan finds its card. On QEMU, which has no Wi-Fi card, each
says `no controller present, not spawned`
([boot-ad2a58a01](../release-evidence/0.9.3/boot-ad2a58a01/README.md)).

| Chip | State | Rests on |
|---|---|---|
| Realtek RTL8821CE | Works | a HP laptop on a sealed image of main at 0bd7c2263, his words only ([drivers/rtl8821ce](../release-evidence/0.9.3/drivers/rtl8821ce/README.md)); the developer report of 6 October 2026 |
| Realtek RTL8822CE | Modelled only, 2.4 GHz | host proofs, [rtl8822ce.md](../drivers/wifi/rtl8822ce.md) |
| Realtek RTL8852BE | Modelled only, 20 MHz | host proofs, [rtl8852be.md](../drivers/wifi/rtl8852be.md) |
| MediaTek MT7921, MT7922, MT7920 | Modelled only; firmware from the boot medium's package | host proofs, [mt7921.md](../drivers/wifi/mt7921.md) |
| Intel AX211, and AX201 on SO platforms | Modelled only | host proofs, [iwlwifi.md](../drivers/wifi/iwlwifi.md) |
| Intel BE200, BE201 | Modelled only | host proofs, [iwlwifi.md](../drivers/wifi/iwlwifi.md#be200-and-be201) |
| Other Intel cards | Refused | [iwlwifi.md](../drivers/wifi/iwlwifi.md#which-cards-do-what) |

"Modelled only" means the driver has run only in its proof crate, against a
model of the chip, and never on a card ([Wi-Fi
drivers](../drivers/wifi/README.md)).

### Wired Ethernet

On QEMU, a standard development image of s4/drivers at 4b1eeb014 got a DHCP
lease through each of the e1000, e1000e, igb, RTL8139, PCnet, vmxnet3 and
Tulip models, with only that card's driver spawned
([drivers](../release-evidence/0.9.3/drivers/)). Traffic past the lease was not
shown, and no wired card has a hardware report. QEMU has no RTL8169 model, so
that driver's receive fix is proven on the host only ([The receive
fault](../drivers/ethernet/README.md#the-receive-fault)).

### IOMMU

The kernel drives both Intel VT-d and AMD-Vi in every build profile:
`microkernel-core` carries `nonos-iommu-enforce`, `nonos-iommu-intremap` and
`nonos-iommu-amdvi` (`Cargo.toml`). Under QEMU's AMD IOMMU the boot prints
`[AMD-VI] IOMMU translation enabled, units=1` and `[IOMMU] amd-vi present,
enforcing=1`
([amd-vi.serial.log](../hardware/evidence/2026-10-25/i7-seeded-iommu/amd-vi.serial.log)).
AMD-Vi has not run on an AMD machine. See [IOMMU](../kernel/iommu.md).

On a standard boot, two vendor drivers may share an isolation group when only a
port without ACS joins their devices. Each keeps its own IOMMU domain
(82ee1a3110). [Security limits](0.9.3-security-limits.md) says what that
leaves open.
