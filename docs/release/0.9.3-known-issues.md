# NONOS 0.9.3 release notes: Known issues

Part of [NONOS 0.9.3 release notes](0.9.3.md).

## Known issues

The evidence directories named below are under
[docs/release-evidence/0.9.3](../release-evidence/0.9.3/README.md).

### Linux apps

- A Linux app's home is held in memory, up to 16 MiB (the Monero wallet's
  64 MiB, `userland/capsule_linux/src/linux/app/home_listings.rs`) and 128 names
  (`HOME` and `HOME_NAMES` in
  `userland/capsule_linux/src/linux/file/system/declared/home.rs`), and is
  gone at power off. A home kept across a reboot is designed and not in this
  release ([Kept homes and installs](../design/kept-homes-and-installs.md)).
- One file an app writes may fill its home and no more. A write past the
  home fails, and the app's window says so once a run, with the home's size
  (`userland/capsule_linux/src/linux/file/system/space/home_room.rs`); no file
  may pass 64 MiB (`MAX_FILE` in
  `userland/capsule_linux/src/linux/file/held/cache/table.rs`, bd27ab42d4).
- An install fetches one package at a time (285d15b7e6). More at once waits
  for route streams that name themselves.
- The Monero wallet's first refresh after it opened could fail with
  "net.socks5 sent an answer this cannot read" while the next connected. An
  open now greets the proxy only after a reset it took (028cba41d7, proven
  on the host); no boot has shown that first refresh connect yet. Keep the
  seed on paper; after power off it is the only copy.
- The Marketplace's proof of how a program ran has not finished on a boot: it
  timed out in two boots, and the 180 s wait that followed (115e2828a7) is not
  booted ([s3-boot1](../release-evidence/0.9.3/s3-boot1/README.md),
  [s3-boot3](../release-evidence/0.9.3/s3-boot3/README.md)).
- Seen on development boots and not shown fixed: lame ends on signal 11
  ([s3-boot2](../release-evidence/0.9.3/s3-boot2/README.md)); micro opened from
  the Marketplace stops on `open /dev/tty`
  ([gui-store-tty-open](../release-evidence/0.9.3/gui-store-tty-open/README.md));
  age's passphrase prompt, written to `/dev/tty`, does not show
  ([s3-boot1](../release-evidence/0.9.3/s3-boot1/README.md)).

### The wallet

- On a machine with no TPM, "Create a wallet" makes the keyring capsule trap and restart, and the wallet says
  `the keyring did not answer: try again in a moment`. It should say there is no machine key to seal under
  ([wallet-no-tpm-kvm](../release-evidence/0.9.3/wallet-no-tpm-kvm/README.md)).

### Not in this release

- SimpleX's desktop window. SimpleX comes as its terminal client. No boot has
  shown it reach an SMP server, or darkirc join its peers
  ([SimpleX Chat](../using/simplex.md)). DarkFi's chat app is listed, and no
  boot has shown its window.

### Linux windows

- mpv and zathura are listed, but no boot in the evidence shows their
  windows (afa860e173, 72a00617a5). Mousepad is not listed for 0.9.3: on the
  release tree it showed no window (a4a26fcc01).
- Telegram Desktop's window is shown, on a KVM run of the release tree
  after an install from the real Alpine mirror, but not a sign-in or a
  message sent ([gui-telegram](../release-evidence/0.9.3/gui-telegram/README.md)).
- Copy and paste between a Linux window and the desktop is tested on the host
  only. Dragging a Linux window by its title bar and minimising it are not
  shown ([gui-frame](../release-evidence/0.9.3/gui-frame/README.md)).

### Hardware

- Only the RTL8821CE has run on a Wi-Fi card. The RTL8822CE, RTL8852BE,
  MT7921 family and every Intel card have run only against a modelled device.
  See [Supported hardware](0.9.3-supported-hardware.md).
- The wired drivers got a DHCP lease on QEMU. No traffic past the lease is
  shown, and no wired card has a hardware report
  ([drivers](../release-evidence/0.9.3/drivers/)).
- AMD-Vi has run only under QEMU's AMD IOMMU, not on an AMD machine.
- Physical memory above 64 GiB is not used. See [Frame
  allocator](../kernel/frame-allocator.md).
- Booting with Secure Boot on is not tested in this release, and an update
  from one release to another is not tested either. See
  [Requirements](../install/requirements.md) and [Update](../install/update.md).
