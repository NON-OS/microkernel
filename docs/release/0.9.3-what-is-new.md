# NONOS 0.9.3 release notes: What is new

Part of [NONOS 0.9.3 release notes](0.9.3.md).

## What is new

The evidence directories named below are under
[docs/release-evidence/0.9.3](../release-evidence/0.9.3/README.md). Unless a
line says otherwise, they are development images booted under QEMU.

### Linux programs in their own windows

- The Linux personality carries a Wayland bridge. A program whose box grants
  WAYLAND opens its own window inside the NONOS frame, with a title bar,
  close, minimise and maximise (53d8f03bf4, 272b635d32). DejaVu fonts are
  stored for window programs (ca7275f90).
- swayimg draws its window, zooms and closes
  ([gui-swayimg](../release-evidence/0.9.3/gui-swayimg/README.md)). The
  frame's close button ends it with status 0, and maximise keeps the title
  bar ([gui-frame](../release-evidence/0.9.3/gui-frame/README.md)).
- KeePassXC 2.7.8 (Qt 5) draws its welcome screen in a box with no network,
  once the personality served FUTEX_WAKE_OP (ceb0f0ee6a,
  [gui-keepassxc](../release-evidence/0.9.3/gui-keepassxc/README.md)).
- Telegram Desktop 5.0.1 (Qt 6) draws its welcome screen in the frame on a
  development image, in a box of WAYLAND, FILES_HOME and NET_ANON, once
  `/proc` answered a thread's own number (71e34654ac,
  [gui-telegram](../release-evidence/0.9.3/gui-telegram/README.md)). A sign-in
  is not shown: that test machine reached only the package mirror.
- foot 1.17.2 is listed in a box of WAYLAND, TTY, FILES_HOME and EXEC
  (fbbd8c5f80). It drew its window and ran a shell over `/dev/pts` on a
  development image ([gui-foot](../release-evidence/0.9.3/gui-foot/README.md)).
- mpv 0.38.0, drawing to `wl_shm` with no GPU (`--vo=wlshm`), and Mousepad
  0.6.2, a GTK text editor, are listed (fbbd8c5f80). zathura 0.5.6 is listed
  with its mupdf PDF plugin, which the listing adds to the install
  (c7bc7960c4, 1a48cc9bef). For these three, no boot in the evidence shows a
  window.
- 304 packages were verified in one boot, KeePassXC and gnome-authenticator
  among them, with no stall, lock wait or OOM
  ([gui-large-installs](../release-evidence/0.9.3/gui-large-installs/README.md)).
- A run's private directories (`/tmp`, `/run/user/0`) hold 1536 names, where
  they held 128. GTK's mime database is built whole there before the program
  starts and kept as its caches, fifteen names, so GTK and Qt programs no
  longer stop on ENOSPC (b7521ace2b, `PRIVATE_NAMES` in
  `userland/capsule_linux/src/linux/file/system/declared/sizes.rs`).
- GTK's preparation tools run before the program's guest is made, so a GTK
  program's run is noted to the seal; before, every GTK program's run went
  unnoted and unkept (fd2a80e365). A KVM run on that commit drew KeePassXC
  2.7.8's window with no ENOSPC and no seal refusal. No log of that run is
  committed.
- A program that asks EGL for OpenGL is pointed at Mesa's software driver,
  drawing through Wayland, where its box's package closure carries that
  driver (`userland/capsule_linux/src/linux/env.rs`, 1f56b890a6). A surface's
  frame callbacks are answered at most 30 times a second, and at once for an
  idle window (`userland/capsule_linux/src/linux/wayland/pace_rule.rs`,
  664185e8a8).

### Pseudo-terminals

- A Linux program can open `/dev/ptmx` and `/dev/pts/N`, as a terminal
  emulator does before it starts its shell (1c81ded90a). See
  [Pseudo-terminals](../userland/linux-personality.md#pseudo-terminals).
- A family holds at most 64 pairs (`MAX` in
  `userland/capsule_linux/src/linux/pty/table.rs`). A master writing with no
  reader stops at 4096 pending bytes or lines and 64 KiB of output, and
  keeps each signal it raises once (ec07d31412).

### The Monero wallet over Nym and Anyone

- `linux.monero` starts `monero-wallet-cli` against the listing's node,
  `xmr-node.cakewallet.com:18081`, with `--untrusted-daemon`, and keeps its
  log to 1 MiB in one file (`userland/capsule_market/linux-catalogue.json`,
  1addaf292b). See [Monero wallet](../using/monero.md).
- On a KVM host the wallet synced from that node over Anyone and over Nym,
  on development images
  ([s1-g-kvm](../release-evidence/0.9.3/s1-g-kvm/README.md)). Serial shows the
  streams; the window's progress is quoted from the notes of those runs.
- The fixes behind it: net.anon picks an exit that takes the stream's port
  (b5876fcae6); an install reads its arguments from its first instruction
  and gets its 320 MiB heap (b5bb69a407); `get_robust_list` is answered, so
  LMDB's lock and the ring database open (e16e16d6b4); a stored file mapped
  shared, as LMDB maps one, is served (373e35a4d5,
  [s1-shared-maps-0d0cff02d4](../release-evidence/0.9.3/s1-shared-maps-0d0cff02d4/README.md)).

### Installing Linux apps

- An install fetches one package at a time over its kept stream, since both
  proxies keep one stream per caller. Three at once had left every package
  unanswered (9fc7634b39, `install_window_tests.rs`). A lone stream had
  brought the 24.7 MB Monero package from the real Alpine mirror whole
  ([s1-g-kvm](../release-evidence/0.9.3/s1-g-kvm/README.md),
  `diag-694ba69799-realmirror-anyone.log`).
- A failed install says which package and which check stopped it, for
  example `libzmq-4.3.5-r2 (its checksum did not match the signed index)`,
  in the Terminal's `market` commands and the Marketplace (e3bed0a8f0).
- An install holds one package about twice its installed size, where it held
  it three times, and checks that it fits the heap left before unpacking it.
  A package that cannot fit ends the install with "Too little free memory to
  unpack one of its packages; close other apps, then retry" and the package's
  name, never a fault. An install takes 640 MiB where 2 GiB is free, then 320
  MiB, then 160 MiB (f03a6abe69). On the owner's 8 GB HP laptop, Telegram
  Desktop's install had stopped with code 134. In a KVM run with 4 and 8 GiB
  guests, Telegram's own package peaked at 143 MiB.
- A need that several packages provide takes the provider an earlier install
  placed, instead of the index's first (5dcb276cc4). Telegram Desktop's
  install after KeePassXC's had been refused for taking `icu-data-en`, which
  holds the same file as KeePassXC's `icu-data-full`. In a KVM run, the same
  install placed `icu-data-full` again, with no refused member.
- The file store may give its clients' files a quarter of memory, between
  160 MiB and 4 GiB, and halves its ask when a heap cannot be mapped
  (f8f2f81c74, `userland/capsule_vfs/src/store/fdtable/budget_size.rs`).
- A program may be up to 128 MiB (36310ba533,
  `userland/capsule_linux/src/linux/program_max.rs`).
- One file a Linux app writes may fill its home, 16 MiB, where it was held to
  8 MiB. A write past it fails with EFBIG, and the first refusal in a run
  prints `linux: this app wrote a file past 16 MiB, the most one file may hold
  here; that write was refused.` in the app's window (38f906c9c7).

### Update NØNOS (keep my data)

- A disk installed by 0.9.3 or later can be updated in place to a later
  release and keep its encrypted data volume. The installer rewrites the boot
  partition and the store and nothing else (8587032e4b, `keep_queue` in
  `userland/nonos_disk/src/session/queue_keep.rs`). See
  [Update](../install/update.md).
- A new data volume's key is random, wrapped under a key the TPM gives only
  a kernel the release approved (85a8d41ac1). A one-boot handover, prepared
  from the installed system, carries it across a new bootloader (7ff8129c52).
  See [The handover](../security/device-secrets-and-keys.md#the-handover).
- On QEMU with a software TPM, a prepared volume opened under an image with a
  changed bootloader, through the handover and then under that bootloader's
  own key
  ([s1-k1-update](../release-evidence/0.9.3/s1-k1-update/README.md)).
- A disk made before 0.9.3 cannot be kept: its data volume is keyed to its own
  kernel, and the installer says `NØNOS keyed to its own kernel: its data
  cannot be kept` (`MadeBefore` in `userland/nonos_disk/src/keep/why.rs`).
- A USB stick booted beside an installed disk comes up as the stick
  (9eb8a850bb); on the owner's HP laptop it had come up as the installed
  system. The loader takes no other disk's store on a USB boot and recognises
  its own disk by its GPT partition GUID. The kernel never keeps another disk
  on a USB boot, and `log BLOCK` says why a boot kept the disk it did. In a
  KVM run, a new stick beside an installed NVMe disk came up with the stick's
  store (`[STORE] the loader's copy of the store: 88369152 bytes`) and setup
  at its first step, and the NVMe disk alone came up as the installed
  desktop. No log of that run is committed.

### The Marketplace

- The catalogue holds 30 recipes
  (`userland/capsule_market/linux-catalogue.json`). A release image lists its
  26 Alpine apps, each in its own box, among them KeePassXC, Telegram
  Desktop, Mousepad, foot, mpv, zathura, swayimg, the Monero wallet,
  Profanity, age, git and vim.
- Open on a terminal program runs it in the Terminal (c55d58e10,
  [gui-store-tty-open](../release-evidence/0.9.3/gui-store-tty-open/README.md)).
- The other four are SimpleX Chat's terminal client
  (`linux.kali.nonos-simplex-chat`, d8e427216b) and DarkFi's `drk`, `darkirc`
  and `darkfid` (1a17cb72ad). They come from a NONOS package mirror. A seal
  lists them only when `nonos.toml` names a mirror and their built content
  (`linux_packages`, `linux_sources`, 2c9ecace25), and both are empty, so a
  release image built from this tree does not list them. See [Apps built from
  source](../userland/marketplace-catalogue.md#apps-built-from-source).

### Drivers

- On QEMU, the e1000, e1000e, igb, RTL8139, PCnet, vmxnet3 and Tulip drivers
  each got a DHCP lease through their card
  ([drivers](../release-evidence/0.9.3/drivers/)). The 0.9.2 receive fault of
  e1000 and RTL8139 is shown fixed on a boot. See [The receive
  fault](../drivers/ethernet/README.md#the-receive-fault).
- The owner reports RTL8821CE Wi-Fi working on their HP laptop, on their seal
  of main 8f2d183dda. It is their report only, with no log
  ([drivers/rtl8821ce](../release-evidence/0.9.3/drivers/rtl8821ce/README.md)).
- New Wi-Fi drivers for the RTL8822CE, RTL8852BE, MediaTek MT7921, MT7922 and
  MT7920, and Intel BE200 and BE201, run only against modelled devices. See
  [Supported hardware](0.9.3-supported-hardware.md).

### Setup, the desktop and the Terminal

- First-boot setup has 13 steps (`STEPS` in
  `userland/capsule_setup_wizard/src/render/layout.rs`), and the gate boots
  walked all 13 to the desktop
  ([gate-a7af21a70](../release-evidence/0.9.3/gate-a7af21a70/README.md)).
  Setup, About and the Terminal show the release from `VERSION`, 0.9.3
  (f68bb8ac3a). See [First boot](../install/first-boot.md).
- Power Off in the desktop's menu, and the Power key, ask "Power off and wipe
  memory?" and then power off through the wipe. See [Keys the desktop
  answers](../using/desktop.md#keys-the-desktop-answers). A development boot
  held a secret in RAM 8 times before Power Off and none after
  ([zs-6d87d9aff](../security/privacy-evidence/2026-10-25/zs-6d87d9aff/README.md)).
- With no IOMMU in service, the splash says `device DMA not confined by
  hardware` in red
  ([gpu-469dddb58-no-iommu](../release-evidence/0.9.3/gpu-469dddb58-no-iommu/README.md)).
- The Terminal gained history search, a hint bar, Ctrl+Alt+T, the git branch
  and jobs in its prompt, AA contrast on every theme, a theme picker, split
  view, the F12 drop-down and `latency`, each booted (terminal-01 to
  terminal-14). A password prompt is not shown as it is typed (717a125504).
  See [Terminal](../using/terminal.md).
