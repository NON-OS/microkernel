# NONOS 0.9.2 release notes: Isolation and the kernel

Part of [NONOS 0.9.2 release notes](0.9.2.md).

### Isolation and the kernel

- On Intel VT-d machines the IOMMU confines device DMA. Every image turns
  translation on at boot and denies a device the boot scan did not find. Each
  driver capsule gets its own IOMMU domain, so a PCI device it claims behind a
  unit in service reaches only the buffers granted to it, and a claim that unit
  cannot confine is refused. See [IOMMU](../kernel/iommu.md).
- Device drivers answer only the services named for them. A wired card's driver
  takes only `net.core` and `net.l2`, a Wi-Fi card's driver takes `net.core`,
  Settings and setup, the USB controller takes the USB keyboard and storage
  drivers, and the keyboard drivers take only the kernel. No other program can
  put raw frames on the wire or read keystrokes from a driver. See [Who may talk
  to a driver](../drivers/README.md#who-may-talk-to-a-driver).
- The NVMe, SATA and virtio-blk drivers serve raw sectors only to the kernel's
  own client and to holders of the StoreWrite capability, and ask the kernel on
  every request. See [Storage drivers](../drivers/storage/README.md).
- The file store answers only the kernel and holders of the FileSystem
  capability. See [Design principles](../overview/design-principles.md).
- A send by process id must pass the gate of every endpoint the target serves,
  as a send by name does. See [IPC](../kernel/ipc.md).
- Releasing a device stops its bus mastering before its DMA buffers are freed,
  and `MkMunmap` or a fixed `MkMmap` over the broker's device windows is
  refused. See [The broker ABI](../abi/broker.md) and [Hardware
  broker](../kernel/hardware-broker.md).
- Inboxes are budgeted in bytes as well as messages: 96 MiB for all inboxes
  together, 16 MiB for one inbox, and half of that for one sender. One caller
  holds at most 8 of the 64 replies a service may owe. Each call carries its own
  correlation token, and a reply reaches only the caller with that token. See
  [IPC](../kernel/ipc.md).
- Init's watch list names 30 core services, among them the network stack, the
  file store, the keyring and the display. When one ends, init starts it again,
  at most 8 times. Drivers, apps, setup, the installer and the Linux personality
  end on purpose and are not restarted. See [Architecture in one
  diagram](../overview/architecture.md).
- The kernel clock multiplies in 128 bits, so it does not wrap on a long uptime.
  See [Timers](../kernel/timers.md).
- The `hardened` and `airgapped` build profiles drop `capsule-serial-debug`, so
  no capsule there gets the Debug grant that lets it write to the serial
  console. See [Logging](../kernel/logging.md).
- A driver that starts through the shared bring-up in `nonos_libc` exits at once
  with status 2 when its device is absent. A device that fails bring-up is tried
  7 times, with a pause that starts at 100 ms and doubles up to 3.2 s, and the
  driver then exits with status 6. The kernel prints an `[EXIT]` line for a
  driver that ends with a nonzero status, so the console says why even when the
  driver holds no Debug. See [Drivers](../drivers/README.md) and
  [Logging](../kernel/logging.md).
- `scripts/cap_audit.py --strict` compares every capsule's capability mask with
  the calls its code makes, and `scripts/check_mirror_caps.py` holds each kernel
  spawn file and README to its manifest. At this commit the strict audit reports
  no failures, with the `attack` and `toolkit` capsules exempt, and the mirror
  check finds no grant wider than its manifest. See [Design
  principles](../overview/design-principles.md) and [Checking the security
  claims yourself](../security/checking-the-claims.md).

### Drivers and the build

- The NVMe driver refuses a doorbell stride that would reach past the registers
  it mapped, waits as long as the controller's CAP.TO asks, up to 127.5 s, and
  keeps each command within MDTS. See [NVMe](../drivers/storage/nvme.md).
- The HD Audio driver binds MSI-X, then MSI, then a legacy line when firmware
  routed one, and otherwise runs polled, so a controller whose firmware left no
  interrupt line is still driven. See [Audio drivers](../drivers/audio.md).
- The seal's last check rebuilds the kernel and the loader with `nix build` and
  stops unless they are the bytes it sealed. See [Reproducible
  builds](../build/reproducible-builds.md).
