The boot chain, from the artifacts themselves

No fixture stands on the trust path here. The shipping kernel image carries its proof in its own footer; the bootloader binary carries the root it enforces. This page parses the footer, measures the 90 MiB kernel body in WebAssembly, extracts the root from inside the EFI, and closes the chain. What a green verdict proves

That this trailer is a valid STARK membership proof under the root above, bound to exactly the measurement, capability mask and epoch shown on its row, at the parameters compiled into the verifier. Contexts are rebuilt from the values on this screen, so what verifies is precisely what you read; a served file cannot bind anything else. The WebAssembly is the deployment's own verify_attestation_trailer, built from NON-OS/stark-attest and reproducible bit for bit.

It does not prove the binary you run is this one. That link is the BLAKE3 column, which you check with b3sum against a downloaded release. A capability listed here is one the proof itself binds, not a line in a configuration file.

The parameters

Width-8 Poseidon at 32 rounds with the x⁷ S-box. Round constants are derived from a public rule and re-derived independently in CI on every push; the diffusion matrix is a Cauchy matrix, MDS by theorem rather than by search. FRI runs 32 queries with 16 grinding bits over a blowup of 4 bits. Soundness is published under both the provable floor and the conjectured model, side by side. There are no elliptic curves anywhere in the construction.
